# Управление бронью

Заявки приходят в существующий закрытый канал Telegram. Управлять ими могут
только создатель и администраторы этого канала.

1. «Подтвердить» занимает места и оставляет под заявкой кнопку «Снять бронь».
2. «Отклонить» освобождает места неподтверждённой заявки.
3. «Снять бронь» освобождает места подтверждённой заявки. В сообщении остаётся
   отметка, кто и когда снял бронь; кнопка исчезает.

Схема сайта получает статусы заново при возвращении на вкладку и каждые
30 секунд, пока вкладка видна. Обновление страницы также загружает статусы.
Подтверждённые заявки не удаляются при очистке старых записей.

Если сохранение статуса прошло, а обновление сообщения Telegram не удалось,
повторное нажатие восстанавливает сообщение без повторного изменения брони.
Ошибка сервиса показывается администратору отдельным уведомлением.

## Размещение

- Страницы: GitHub Pages, существующий workflow `.github/workflows/deploy.yml`.
- Обработка заявок и состояние мест: существующая Yandex Cloud Function
  `ngperm-booking`, Node.js 22, `index.handler`, сервисный аккаунт и бакет сохраняются.
- Релей: существующий Cloudflare Worker `ngperm-tg-relay`. Webhook Telegram
  остаётся на ранее настроенном адресе `/hook`; секреты не меняются.
- Обработка релея закреплена рядом с `aws:eu-north-1`: из узла DME запросы
  к Telegram зависали. Публиковать конфигурацию нужно Wrangler 4 с поддержкой
  `placement.region`; старый Wrangler 3 это поле не поддерживает.
- Дополнительный адрес того же релея: `https://relay.ngperm.ru`.
  Основной домен `ngperm.ru` и его записи GitHub Pages не меняются.

Переменные окружения функции:

| Переменная | Значение / назначение |
| --- | --- |
| `TELEGRAM_API_BASE` | `https://relay.ngperm.ru` |
| `TELEGRAM_RELAY_CONNECT_HOST` | `cdnjs.cloudflare.com` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_RELAY_KEY`, `TELEGRAM_WEBHOOK_SECRET` | Существующие секреты, только в облаке |

31.10.2026 соединение из функции Яндекса с обычными адресами релея
зависало на TLS. Для соединения используется доступный адрес сети Cloudflare,
полученный из DNS `TELEGRAM_RELAY_CONNECT_HOST`. HTTP Host, TLS SNI и проверка
сертификата остаются привязаны к **relay.ngperm.ru**. Запросы не отправляются
на сервис cdnjs; меняется только выбор адреса узла той же сети Cloudflare.
IP-адреса и сертификаты не закрепляются в коде. Полный срок запроса ограничен
5 секундами, включая DNS и TLS; таймаут выполнения функции — 40 секунд.

Релей подтверждает webhook только после успешной обработки в Яндексе.
При ошибке возвращается 503, чтобы Telegram повторил доставку.
Повторные действия обрабатываются идемпотентно.

## Проверка и публикация

`npm test --prefix server` проверяет снятие, повторное нажатие после сбоя,
права доступа, сохранение старых подтверждённых заявок и сетевые ошибки.
`npm run build` проверяет сборку сайта.

Пуш в GitHub обновляет **только сайт**. Для серверных изменений отдельно
публикуются файлы `server/index.js`, `server/lead-handler.js`, `server/store.js`,
`server/telegram.js`, `server/package.json` в существующую функцию, с сохранением
всех переменных окружения и сервисного аккаунта. Релей публикуется из
`server/relay/` с сохранением его четырёх существующих секретов и дополнительного
домена. При откате выбирается прежняя версия функции; состояние броней не откатывается.

Проверки интерфейса должны подменять ответы функции, а не отправлять тестовые
заявки в настоящий канал. `scripts/qa-mobile.mjs` перехватывает эти запросы.
